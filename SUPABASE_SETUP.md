## Security boundaries

- `@supabase/ssr` uses async Next.js cookies and `src/proxy.ts` refreshes sessions only for `/admin/:path*`, including login. Refreshed cookies/cache headers are preserved. All admin responses use private/no-store and noindex headers; the admin layout is dynamic and has noindex metadata.
- The SDK runs exclusively on the server. Cookies are HttpOnly, SameSite=Lax, path `/`, and Secure in production. No browser client or public-prefixed environment values are needed; the existing same-origin CSP remains unchanged.
- `requireAdmin()` calls Auth `getUser()` for a fresh server-confirmed identity, compares the exact UUID to the server environment, then calls `is_portfolio_admin()` to confirm the database allowlist. The Proxy's verified claims are for refresh, not the authorization boundary. No `getSession()` identity or user metadata is trusted.
- The `/admin` page, each data/storage access function, and the logout mutation authorize independently. Future admin reads and mutations must call `requireAdmin()` at their own entry point, validate untrusted inputs, and use its session-bound client. Never cache an authorized client across requests, use a privileged client, or rely only on a layout or Proxy. Content CRUD is reserved for later authorized steps.
- Failed login has a fixed generic response and clears the local session. Redirects have fixed local destinations. Missing configuration disables login and denies protected access. Provider failures/DB allowlist mismatches deny access.
- Each content table has RLS enabled and forced, explicit CRUD privileges only for `authenticated`, and both `USING`/`WITH CHECK` tied to the private allowlist. The security-definer boolean function has an empty search path, fully qualified objects and no public/anonymous execute grant. It accepts no caller-selected UUID. Postgres administrative roles can bypass RLS by design and must stay outside the application.
- Storage permits admin-only operations in the private `portfolio-media` bucket, capped at 10 MiB for JPEG/PNG/WebP/PDF. Restrictive guards also prevent broader existing permissive policies from granting anonymous/non-admin access to this bucket. Metadata records in `media` and actual Storage uploads are separate; later upload/delete flows must coordinate them through the Storage API. No public bucket, public URL, signed URL, or upload endpoint is added. On an existing project, audit pre-existing Storage policies and exposed functions before use. Use a dedicated project rather than importing unreviewed policies.
- To revoke access immediately, remove the private allowlist row (and remove/change the server UUID) and revoke the user's Auth sessions. Removing the DB row blocks future RLS operations even while an issued JWT remains valid. Rotating admins requires updating both locations; a mismatch fails closed.

## Diagnose media registration after optional alt text

The generic unconfirmed-change message alone does not identify the failing stage: the server action uses it for Storage errors, RPC errors, unexpected RPC response shapes and exceptions. Migration 007 removes this guard. Its existence in the workspace does not mean it has been applied to the configured database. A nonempty-alt upload succeeding while an empty-alt upload fails is supporting evidence, but do not create more uploads just to diagnose this.

Run these **read-only** queries as the database owner in the configured project's Supabase SQL Editor. They return schema diagnostics without keys, image bytes or profile content:

```sql
with routine as (
  select to_regprocedure('public.write_media_editor(uuid,integer,text,jsonb)') as oid
), definition as (
  select oid, pg_get_functiondef(oid) as sql from routine
)
select oid is not null as media_rpc_exists,
  coalesce(position($guard$(role_name<>'cv' and btrim(metadata->>'alt_text')='')$guard$ in sql) > 0, false)
    as has_known_004_blank_alt_guard,
  coalesce(position($default$coalesce(metadata->'alt_text','""'::jsonb)$default$ in sql) > 0, false)
    as has_007_optional_alt_validation
from definition;

select c.conname, pg_get_constraintdef(c.oid) as definition
from pg_constraint c
where c.conrelid = 'public.media'::regclass
  and pg_get_constraintdef(c.oid) ilike '%alt_text%';
```

```sql
select o.name, o.created_at, o.updated_at
from storage.objects o
where o.bucket_id = 'portfolio-media'
  and o.name ~ '^photo/[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}[.](png|jpg|webp)$'
  and greatest(o.created_at, o.updated_at) < now() - interval '24 hours'
  and not exists (select 1 from public.media m where m.object_path = o.name)
order by o.created_at desc;
```
